# Control Signals, ALU Control, and Opcode Reordering: Design Notes

Opcode bits are written `o3 o2 o1 o0` (o3 is the MSB, bit 9 of the instruction). `Dn` means "decoder output n", which is true when the opcode equals n.

---

## 1. Control signals

The control unit has two kinds of outputs:

- **Direct taps:** signals wired straight from opcode bits with no logic. These exist because of the opcode reordering (sections 3 to 5).
- **Decoder-generated:** every other signal. The opcode goes through a 4-to-16 decoder, and each signal is an OR (or AND-OR, for `Branch`) of the decoder outputs for the instructions that need it.

### Decoder outputs

| Output | Instr | Output | Instr |
|---|---|---|---|
| D0 | ADD | D8 | LW |
| D1 | ADDI | D9 | SW |
| D2 | AND | D10 | IN |
| D3 | OR | D11 | OUT |
| D4 | SUB | D12 | BEQ |
| D5 | CMP | D13 | BLT |
| D6 | SLL | D14 | JMP |
| D7 | (unused) | D15 | HALT |

### Signal definitions

| Signal | Width | Drives | Generated by | Equation | Asserted for |
|---|---|---|---|---|---|
| `AluOp` | 2 | ALU function select | **Direct tap** | `o1 o0` | all ALU ops |
| `BInvert` | 1 | ALU B-invert and bit-0 carry-in | **Direct tap** | `o2` | SUB, CMP |
| `WriteBackSrc` | 2 | Write-back mux select | **Direct tap** | `{o3, o1}` | see section 5 |
| `RegWrite` | 1 | Register file write enable | **Decoder** | D0 + D1 + D2 + D3 + D4 + D6 + D8 + D10 | ADD, ADDI, AND, OR, SUB, SLL, LW, IN |
| `Shift` | 1 | ALU result mux: shifter vs. adder/logic | **Decoder** | D6 | SLL |
| `R7` (ALU A source) | 1 | A mux: 0 = ReadData1, 1 = R7 | **Decoder** | D8 + D9 | LW, SW |
| `Imm` (ALU B source) | 1 | B mux: 0 = ReadData2, 1 = SignExt(imm) | **Decoder** | D1 + D8 + D9 | ADDI, LW, SW |
| `MemWrite` | 1 | RAM `str` | **Decoder** | D9 | SW |
| `CMP` | 1 | CmpFlags enable (latch E and L) | **Decoder** | D5 | CMP |
| `Output` | 1 | OBR enable | **Decoder** | D11 | OUT |
| `Branch` | 1 | PC mux select (0 = PC+1, 1 = target) | **Decoder** + E, L | (D12 · E) + (D13 · L) + D14 | BEQ if E, BLT if L, JMP always |
| `Halt` | 1 | PC enable = NOT `Halt` | **Decoder** | D15 | HALT |

`Branch` also needs E and L as inputs to the control unit, so the CmpFlags outputs must be wired back to it.

Not control-unit signals:
- `CLK` is a top-level input to the PC, register file, RAM, CmpFlags, and OBR.
- The IBR is loaded by the external keyboard/Enter, not by the control unit.
- RAM `ld` can be tied to constant 1, since reading memory is harmless when the value is unused (see section 6).

### Truth table (instruction × signal)

`x` means the value is ignored for that instruction. The tapped signals still physically carry whatever the opcode bits are.

| Instr | Opcode | RegWrite | WriteBackSrc | R7 | Imm | AluOp | BInvert | Shift | MemWrite | CMP | Output | Branch | Halt |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| ADD | 0000 | 1 | 00 | 0 | 0 | 00 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| ADDI | 0001 | 1 | 00 | 0 | 1 | 01 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| AND | 0010 | 1 | 01 | 0 | 0 | 10 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| OR | 0011 | 1 | 01 | 0 | 0 | 11 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| SUB | 0100 | 1 | 00 | 0 | 0 | 00 | 1 | 0 | 0 | 0 | 0 | 0 | 0 |
| CMP | 0101 | 0 | x | 0 | 0 | 01 | 1 | 0 | 0 | 1 | 0 | 0 | 0 |
| SLL | 0110 | 1 | 01 | 0 | 0 | x | x | 1 | 0 | 0 | 0 | 0 | 0 |
| (unused) | 0111 | 0 | x | 0 | 0 | x | x | 0 | 0 | 0 | 0 | 0 | 0 |
| LW | 1000 | 1 | 10 | 1 | 1 | 00 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| SW | 1001 | 0 | x | 1 | 1 | 01 | 0 | 0 | 1 | 0 | 0 | 0 | 0 |
| IN | 1010 | 1 | 11 | 0 | x | x | x | 0 | 0 | 0 | 0 | 0 | 0 |
| OUT | 1011 | 0 | x | 0 | x | x | x | 0 | 0 | 0 | 1 | 0 | 0 |
| BEQ | 1100 | 0 | x | 0 | x | x | x | 0 | 0 | 0 | 0 | E | 0 |
| BLT | 1101 | 0 | x | 0 | x | x | x | 0 | 0 | 0 | 0 | L | 0 |
| JMP | 1110 | 0 | x | 0 | x | x | x | 0 | 0 | 0 | 0 | 1 | 0 |
| HALT | 1111 | 0 | x | 0 | x | x | x | 0 | 0 | 0 | 0 | 0 | 1 |

Safety properties of this design:
- Unused opcode 0111 writes nothing, stores nothing, and does not branch.
- Only SW asserts `MemWrite`, only CMP asserts `CMP`, and only OUT asserts `Output`.
- Because `Shift` comes from the decoder (D6) rather than an opcode tap, it is 0 for every instruction except SLL.

## 2. Summary of changes

| Change | Effect |
|---|---|
| Reorder opcodes 0000 to 0110 (ADDI, SUB, SLL move) | `BInvert` and `AluOp` become direct taps of opcode bits, with no gates |
| Rewire the 1-bit ALU result mux (sum on inputs 0 and 1) | `AluOp = opcode[1:0]` works for every ALU instruction, including LW and SW |
| Add a `Shift` input to the 10-bit ALU, driven by decoder output D6 | Replaces the AND gate on `AluOp` that used to select the shifter |
| Single 2-bit `WriteBackSrc` control, tapped from `{o3, o1}` | One 4:1 write-back mux, no gates, and no separate `MemToReg` or `IBRToReg` |
| Dedicated `R7` output from the register file | No read-register muxes. One 10-bit mux on the ALU's A input |
| Hybrid control unit: direct taps plus a 4-to-16 decoder | ALU-facing signals and the write-back select are free. Everything else is a readable OR of instructions |

## 3. Opcode reordering

Only opcodes 0000 to 0110 move. Everything from 1000 up (LW, SW, IN, OUT, BEQ, BLT, JMP, HALT) is unchanged.

| Instruction | Old opcode | New opcode |
|---|---|---|
| ADD | 0000 | 0000 |
| **ADDI** | 0110 | **0001** |
| AND | 0010 | 0010 |
| OR | 0011 | 0011 |
| **SUB** | 0001 | **0100** |
| CMP | 0101 | 0101 |
| **SLL** | 0100 | **0110** |
| (unused) | 0111 | 0111 |

### Why

The ALU needs only a handful of behaviours:

| Behaviour | Used by |
|---|---|
| Add | ADD, ADDI, LW, SW |
| Subtract (add with B inverted) | SUB, CMP |
| AND | AND |
| OR | OR |
| Shift left | SLL |

The new ordering is built around two observations:

1. **`o2` can be the B-invert bit.** Every instruction that needs B inverted (SUB, CMP) is placed in the `o2 = 1` half of the opcode space. Every other instruction that uses the ALU adder or logic has `o2 = 0`.
2. **`o1 o0` can pick the function.** Within each half, the low two bits are `00`, `01`, `10`, `11`. If the 1-bit ALU's result mux is wired so inputs 0 and 1 both select the adder, then `00` and `01` are both "add", `10` is AND, and `11` is OR. That gives four add-type slots (ADD, ADDI, SUB, CMP), which is why they fit in pairs on either side of `o2`.

SLL sits at 0110, where `o1 o0 = 10` would select AND on its own. That's fine because `Shift` overrides the result mux, so the adder/logic output is never used for SLL.

In the original ordering, SUB and CMP (0001 and 0101) shared only `o0 = 1`. `BInvert` needed `¬o3 · ¬o1 · o0` and `AluOp` needed several gates.

## 4. How `AluOp`, `BInvert`, and `Shift` are generated

| Signal | Generated by | Definition | Cost |
|---|---|---|---|
| `BInvert` | Direct tap | `o2` | wire |
| `AluOp[1:0]` | Direct tap | `o1 o0` | wire |
| `Shift` | Decoder | D6 | one decoder output |

`Shift` could also be computed as `o2 · o1` with one AND gate (that expression is also true for JMP and HALT, whose ALU results are ignored). Using D6 avoids that ambiguity, since it is true for SLL only.

### 1-bit ALU result mux

| `AluOp` | Mux input | Source |
|---|---|---|
| 00 | 0 | adder sum |
| 01 | 1 | adder sum (same wire as input 0) |
| 10 | 2 | A AND B |
| 11 | 3 | A OR B |

The B-invert mux (input 0 = B, input 1 = NOT B) feeds only the adder. AND and OR use raw B. The 10-bit shifter also takes raw A and B, with the shift amount taken from the low 4 bits of B. `Shift = 1` selects the shifter output at the 10-bit result mux.

Bit 0's carry-in must be tied to `BInvert` (subtract = A + ~B + 1). Each higher bit's carry-in comes from the previous bit's carry-out.

### Per-instruction ALU behaviour

| Instruction | Opcode | `BInvert` (o2) | `AluOp` (o1o0) | `Shift` | ALU does |
|---|---|---|---|---|---|
| ADD | 0000 | 0 | 00 | 0 | A + B |
| ADDI | 0001 | 0 | 01 | 0 | A + B |
| AND | 0010 | 0 | 10 | 0 | A AND B |
| OR | 0011 | 0 | 11 | 0 | A OR B |
| SUB | 0100 | 1 | 00 | 0 | A + ~B + 1 |
| CMP | 0101 | 1 | 01 | 0 | A + ~B + 1 (flags only) |
| SLL | 0110 | 1* | 10 | 1 | A << B[3:0] |
| LW | 1000 | 0 | 00 | 0 | R7 + imm (address) |
| SW | 1001 | 0 | 01 | 0 | R7 + imm (address) |
| IN, OUT, BEQ, BLT, JMP, HALT | 101x, 11xx | x | x | 0 | result ignored |

\* `BInvert` has no effect on SLL because the shifter uses raw B.

**LW and SW** need no special case. Their low bits (00 and 01) already mean "add" and `o2 = 0`, so `o3` is never consulted. The operand routing (A = R7, B = sign-extended imm) comes from the `R7` and `Imm` mux controls (decoder-generated), not from `AluOp`.

**Flags.** `EqualTo` and `LessThan` come from the ALU on every instruction, but they are only latched when `CMP` is asserted, which is only true for opcode 0101 (D5).

## 5. `WriteBackSrc`

A single 2-bit control picks what the register file receives. It is wired straight from the opcode: `WriteBackSrc = {o3, o1}` (instruction bits 9 and 7).

| Instruction | Opcode | o3 | o1 | `WriteBackSrc` | Mux input | Source |
|---|---|---|---|---|---|---|
| ADD | 0000 | 0 | 0 | 00 | 0 | ALU |
| ADDI | 0001 | 0 | 0 | 00 | 0 | ALU |
| SUB | 0100 | 0 | 0 | 00 | 0 | ALU |
| AND | 0010 | 0 | 1 | 01 | 1 | ALU |
| OR | 0011 | 0 | 1 | 01 | 1 | ALU |
| SLL | 0110 | 0 | 1 | 01 | 1 | ALU |
| LW | 1000 | 1 | 0 | 10 | 2 | Data memory |
| IN | 1010 | 1 | 1 | 11 | 3 | IBR |

### Why this works

- Every ALU-type instruction that writes a register has `o3 = 0`. `o1` varies among them (ADD, ADDI, and SUB have 0, AND, OR, and SLL have 1), but it does not matter, so mux inputs 0 and 1 are **both wired to the ALU result**. This is the same don't-care trick used in the 1-bit ALU mux.
- LW (1000) and IN (1010) are the only register-writing instructions with `o3 = 1`, and they differ in `o1`. So `o1` picks memory (input 2) or IBR (input 3).
- SW, OUT, branches, and HALT also land on inputs 2 or 3, but `RegWrite = 0` for all of them, so the mux output is ignored.

### Mux wiring

| Input | Source |
|---|---|
| 0 | ALU result |
| 1 | ALU result |
| 2 | Data memory output |
| 3 | IBR output |

## 6. Review of the current datapath

### Looks correct
- PC feeds the instruction ROM, with a PC+1 adder (constant 1) and a branch adder (PC+1 + SignExt6(offset)).
- The PC mux chooses between PC+1 and the branch target.
- The A mux takes ReadData1 or R7, and the B mux takes ReadData2 or SignExt3(imm).
- RAM address comes from the ALU result. RAM data-in and OBR data-in both come from ReadData1.
- The write-back mux takes the ALU result, RAM output, and IBR.
- CmpFlags takes the ALU's `EqualTo` and `LessThan`.
- `Shift` has been added to the ALU, and the `Input` control signal has been removed.

### Verify in Logisim
Mux input order can't be confirmed from a screenshot, so click each mux and check:

| Mux | Input 0 | Input 1 | Input 2 | Input 3 |
|---|---|---|---|---|
| A (ALU) | ReadData1 | R7 | | |
| B (ALU) | ReadData2 | SignExt3(imm) | | |
| PC | PC+1 | branch target | | |
| Write-back | ALU | ALU | RAM | IBR |

Also check the following:
- The old AND gate on `AluOp` inside the 10-bit ALU is removed, and `Shift` drives the result mux select.
- The ROM and RAM data widths are 10 bits.
- No two wires touch where they cross near the ReadData1 and R7 lines.

### Still missing
1. **`Halt` / PC enable.** The PC needs `en = NOT Halt`.
2. **Clock.** There is no top-level `CLK` pin feeding the PC, register file, RAM, CmpFlags, and OBR.
3. **E and L fed back to the control unit** for the `Branch` equation.
4. **IBR input.** The IBR needs a 10-bit data source (an input pin on D), loaded by the external Enter rather than by the control unit.
5. **OBR output.** Needs a display (hex digit display or output pin) on Q.
6. **The control unit itself** (the `dummy` box). The opcode bits `[9:6]` are already routed to it.

### Optional simplification
- **`MemRead`** is not a needed control signal. Reading memory is harmless when the value is unused: the write-back mux only selects RAM for LW, and `RegWrite` gates everything else. Tie RAM `ld` to a constant 1. If your course requires an explicit `MemRead`, it equals D8.
